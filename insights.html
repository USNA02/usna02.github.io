Insights

How the public projects were read.

Name the row, cite the source, and keep demand separate from pay. Short notes, tied to the repositories.

3 min

Name the row before you aggregate

The cereals series only stays honest if one row means one thing.

On the Kenya cereals project the first question is not the chart. It is what one row represents: a country, an indicator, and a year.

If that sentence is fuzzy, a cereals total can be read as maize, or a national series can be treated as a county table. The repository says what it is not, in the same place as the question.

SQL and Python are there so the comparison can be reproduced. The habit on a client file is the same: count, name the grain, then aggregate.

3 min

Put the source in the same view as the number

A figure without a citation is a claim. The cereals file is World Bank data under CC BY 4.0.

The harvest and yield figures on this site come from World Bank World Development Indicators, read through Our World in Data and a DataHub mirror, downloaded 16 November 2026.

The licence is CC BY 4.0. The citation sits with the finding because a buyer or a reviewer has to know what may be reused and what must be named.

The same rule belongs on a client brief. If a year is missing, leave it blank. The 2024 harvested area in that file was unpublished, so the column stays empty.

4 min

Demand and pay are not the same list

The job-market queries keep those two questions apart.

A skill can be everywhere in analyst postings and still not be the skill attached to higher salaries. Counting mentions answers a different question from averaging pay.

The SQL project asks both, on remote data-analyst roles, and keeps the queries. In that dataset SQL shows up on both lists. Niche skills can post higher averages with far fewer roles.

That is why the repository matters more than a single ranking. Change the filter and the list should change with it.
